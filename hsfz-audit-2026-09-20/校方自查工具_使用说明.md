# 智慧校园平台越权访问自查工具 — 使用说明

配套文件：`校方自查工具_越权检测.py`

本工具用于**学校信息中心自行核查**「智慧校园公共服务平台」的数据权限问题，并在修复后复测验证。

---

## 一、这个工具解决什么问题

该平台所有业务共用一个接口地址，靠 `CODE` 参数区分功能：

```
POST https://TARGET-SSO.example.edu/USER_d9833f/common/queryRemoteData?CODE=<接口编号>
```

实测问题：网关**只校验"是否已登录"，不校验"该角色是否有权查这条数据"**。
结果是——任意一个普通学生账号，就能调用管理类接口读到全校数据。

本工具做的事：用你们自己提供的**低权限账号**跑一遍，把「这个账号能读到什么」逐条列出来，形成可留档、可对比的报告。

---

## 二、运行方式

### 环境
Windows / Linux 均可，**Python 3.8+**，只用标准库，不需要 pip 安装任何东西。

### 第 1 步：拿到 Cookie

1. 浏览器登录 `https://TARGET-SSO.example.edu/USER_d9833f/`
2. 按 `F12` → `Application`（应用）→ `Cookies`
3. 至少复制这两个值：`ssportal_token`、`ssportalcloudsession_id`

### 第 2 步：拿到自己的 userId（建议提供）

`--self-id` 是当前登录账号自己的用户 id。

**为什么需要**：部分管理类接口在缺少 `operatorId` 时，会直接返回"操作者id不能为空"——
王远"读到了数据"，也不是"吕秀"。**如果不提供 self-id，这些接口只会显示
「未能判定」，你们就无法确认它到底修没修好。**

怎么拿：随便调一个返回 `applyUserId` / `operatorId` / `userId` 的只读接口即可看到
（例如留宿记录接口返回的就是自己的 `applyUserId`）。

### 第 3 步：执行

```bash
# 基础自查（约 1 分钟）
python 校方自查工具_越权检测.py ^
    --cookie "ssportal_token=xxx; ssportalcloudsession_id=yyy" ^
    --self-id 1234567 ^
    --school-id 50656 ^
    --account-type 学生 ^
    --outdir 自查结果
```

> Windows 命令行换行用 `^`；PowerShell / Linux 用 `` ` `` 或 `\`。
> 也可以把参数写成一整行。

### 第 4 步（可选）：全量扫描

```bash
python 校方自查工具_越权检测.py --cookie "..." --self-id 1234567 --sweep --limit 300
```

会自动拉取全部接口清单（约 1000+ 个）并逐个判定可达性，耗时较长。
写操作类接口（含 `ADD/EDIT/DELETE/SAVE/MODIFY/IMPORT...` 等动词）**已被自动排除，不会被调用**。

### 第 5 步：修复后复测

修复完成后重跑，加上基线参数，报告会自动标注每一项的变化：

```bash
python 校方自查工具_越权检测.py --cookie "..." --self-id 1234567 ^
    --USER_8ba849 自查结果\自查报告_20260920_1057.json
```

## 三、报告怎么读（重点）

### 判定是**三态**，不是两态

| 严伟 | 金英 | 喻秀 |
|---|---|---|
| **⚠ 放行** | 该账号成功读到了数据 | **这是问题**，需按整改建议修 |
| **已拦截** | 服务端明确拒绝（403/406） | 鉴权生效，无需处理 |
| **未能判定** | 服务端报「柏远」类错误 | **⚠ 这不等于安全**，只是参数没凑齐，需补参后复测 |

**最容易踩的坑**：把「未能判定」当成「已修复」。
一个接口只要返回"操作者id不能为空"这类参数错误，就说明**还没测到鉴权层**，
不能计入整改结果。

### 报告还包含三组对照

1. **鉴权对照组** —— 分别去掉 JWT、置空 token、去掉 Cookie 各测一次。
   若「去掉 JWT」仍返回数据，说明 JWT 根本没参与校验。
2. **分页限制** —— `pageSize=5000` 能否一次拉走全表。
3. **跨租户隔离** —— 换其他 `schoolId` 是否仍能读到数据（用于确认影响范围是否限于本校）。

## 四、安全与合规约束（请务必遵守）

1. **必须使用本单位配发账号**，禁止使用他人账号、禁止共享凭据。
2. 工具**默认不保存任何个人信息明文** —— 报告中只有状态码、记录条数、字段名。
   这是最小化取证原则：证明问题存在不需要留存数据本身。
3. 如确需留存样本用于内部核对，才使用 `--samples N`。**该参数生成的文件属于个人信息载体**，
   请限制访问权限、明确保管责任人，并在核对完成后销毁。
4. 报告输出目录请设置访问权限，**禁止上传至公网或第三方平台**。
5. 自查过程中**不要**对生产数据执行写操作；工具已自动排除写操作类接口，请勿手动绕过。
6. 建议在业务低峰期执行，全量扫描会持续产生请求。

## 五、已实测的接口结构（供排查参考）

网关调用的请求契约（工具已内置，无需手工拼装）：

```
POST /USER_d9833f/common/queryRemoteData?CODE=<编号>
Content-Type: USER_1fe289/json;charset=UTF-8

头：
  x-token        = Cookie 中的 ssportal_token
  USER_cbb82e  = Bearer <auth_token>
  dhash          = md5(请求体JSON + ssportal_token)
  ts             = <毫秒时间戳+随机数>;<md5(同上 + "m-web.etonedu.cn")>
  traceId        = <uuid4>
Cookie: ssportalcloudsession_id / ssportal_token / auth_token
```

常见返回码含义：

| rescode | 金英 |
|---|---|
| 10000 | 成功（数据已返回） |
| 403 | 未登录或会话失效 |
| 406 | x-token 校验失败 |
| 12004 | 参数/组织校验失败（**注意区分是"柏远"赵芳"张芳"**） |
| 90000 | 接口不存在 |

## 六、整改方向（对应报告「整改建议」一节）

问题的根因不在"孔平"，而在**缺少数据权限（行级权限）校验**：

1. 查询类接口默认以**会话持有者**为过滤条件；只有具备相应角色
   （班主任 / 宿管 / 德育 / 管理员）时才允许查询他人数据。
2. 网关层按 `CODE` 建立**角色白名单**，学生角色默认拒绝管理类接口。
3. `pageSize` 服务端强制上限（建议 ≤ 200），防止一次拖走全表。
4. 修复 JWT 未被校验的问题。
5. 接口调用审计：对「单次返回大量个人信息记录」的调用告警。

## 七、测试边界声明

本次评估由校外人员在校方授权下完成，执行过程中：

- **只做只读 GET/POST 查询**，未执行任何写操作、删除操作或数据变更；
- **未下载任何批量数据文件**；
- **未留存任何个人信息明文**；
- 未对账号进行密码尝试或暴力破解。

如需核对数据真实性，请用**管理员账号**在**本单位内网**自行复现，
这比任何外部提供的样本都更具证明力。
