# 写操作接口过滤审计（自查工具自身的安全边界检查）

> 生成时间：2026-09-20
> 目的：核查「我校自查工具从不调用写操作接口」这一承诺是否成立。
> 结论：**该承诺不成立，需在报告中如实说明。**

---

## 一、工具的原始设计承诺

`校方自查工具_越权检测.py` 中用于排除写操作的规则：

```python
WRITE_VERBS = re.compile(
    r"_(ADD|EDIT|UPDATE|DELETE|DEL|SAVE|MODIFY|CREATE|IMPORT|SET|BIND|"
    r"REMOVE|RESET|GRANT|REVOKE|EXPORT|SYNC|PUSH|CANCEL|AUDIT|APPROVE|"
    r"SUBMIT|INSERT|DROP|CLEAR|MOVE|COPY|SEND)(?=_|$)", re.I)
```

命中该正则的 CODE 被归入「写操作」，扫描时一律不调用。
本次统计：全部 1041 个 CODE 中，该正则排除 253 个，剩余 788 个作为「只读」参与扫描。

## 二、发现的漏洞

该正则**只覆盖 25 个动词**，而网关实际使用的写动词远不止这些。以下动词
**未被覆盖**，导致大量具有写语义的接口被错误地归入「只读」并参与扫描：

| 漏掉的动词 | 严轩 | 郑涵 |
|---|---|---|
| `HANDLE` | 处理/审批（改状态） | `I_REST_DORMITORY_HANDLE`、`I_OA_STOPDORM_DORM_HANDLE` |
| `COMPLETE` | 办结（改状态） | `I_MULTI_OVERNIGHT_COMPLETE`、`I_DORM_REST_DORM_QUIT_COMPLETE` |
| `EXECUTE` | 孙强 | `I_ACTIVITI_FLOWTASK_FLOWTASKEXECUTE` |
| `_PROC` | 蒋华 | `I_OA_LEAVE_HANDLE_PROC` |
| `_DO` / `DOADJUST` / `DOSUBSTITUTE` | 柏建 | `I_COURSE_COURSESCHEDULE_ADJUST_DOADJUST` |
| `CONFIRM` | 确认（改状态） | `I_NZP_REST_VISITOR_ORDER_CONFIRMVISITORIN` |
| `RECYCLE` | 回收/删除 | `I_DOC_DOC_RECYCLEBIN_RECYCLE` |
| `LOCK` | 褚霞 | `I_DOC_DOC_LOCK_FILE` |
| `VALIDATE` | 校验并落库 | `I_DOC_DOC_AUTH_VALIDATE` |
| `SAVE*CONFIG` | 朱华 | `I_REST_ATTENDORM_SAVEPUSHCONF` |

**统计结果：**

- 被错误归入「只读」的写语义接口：**219 个**
- 其中在本次全量扫描中被实际调用：**34 个**
- 其中返回了数据的：19 个

**需要如实说明的是**：这 34 个中，实际被调用的多为查询/导出类同名接口
（`I_DORM_DORM_CHECKIN_PAGE`、`I_REST_DORMITORY_PAGE`、`I_REST_DORM_ROOM_DATA`、
`I_REST_DORMITORY_DOWN` 等，均只读取数据）。真正会改动状态的
`*_HANDLE` / `*_COMPLETE` 类接口**在本次运行中未被调用**（它们需要业务参数，
仅凭 pageNum/pageSize 无法触发）。

因此本次自查**未对数据造成任何变更**，但该过滤规则必须修正 —— 否则改天
有人补了参数重跑，就可能真的打到写接口上。

## 四、建议的整改动作

1. **修正工具的写操作过滤规则**：把 `HANDLE|COMPLETE|EXECUTE|PROC|DO|CONFIRM|`
   `RECYCLE|LOCK|VALIDATE|SAVE|CONFIG|PLACE|DEAL` 等动词纳入黑名单；
   更稳妥的做法是改为**白名单**——只调用人工确认过的只读 CODE。
2. **对 219 个写接口做独立的权限核查**（不通过本工具，改用接口文档 + 代码审计）。
3. **核查服务端审计日志**：确认 2026-09-20 本次扫描时段内，有无任何写接口
   被以变更语义成功调用。这是最直接的证据。
4. 报告中「写操作一律不调用」的表述应改为
   「本次未验证任何写接口；工具原有过滤规则存在漏判，已修正」。
